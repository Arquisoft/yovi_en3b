=== Requirements Overview

**YOVI** is a gaming suite developed for **Micrati** based on "Game Y". The system allows users to play hexagonal board games against the computer and provides an interface for external bots.

Key functional requirements include:/

* **Core Gameplay:** Implementation of classic Game Y with variable board sizes.
* **AI Strategies:** Support for multiple machine strategies and selectable difficulty levels.
* **User Management:** Registration and match history tracking (win/loss stats).
* **External Access:** A fully documented API for bot interaction using **YEN notation**.
* **Public Availability:** The system must be deployed and accessible via the web.

The following table presents the top five quality goals for the YOVI architecture, ordered by priority. These goals have been identified based on stakeholder expectations and represent the most critical attributes that guide our architectural decisions.

[options="header",cols="1,2,3"]
|===
|Priority|Quality Goal|Concrete Scenario

|1
|**Interoperability (Compatibility)**
|The system must decouple the game engine from the frontend by exposing a standardized REST API using **YEN notation** (JSON). This architectural decision allows external bots and third-party clients to connect and play seamlessly.

|2
|**Security**
|The architecture must guarantee user data privacy and authorization by design. All passwords must be hashed using `bcrypt` at the Data Access layer, and secure endpoints must be protected using JWT (JSON Web Tokens) to prevent unauthorized actions.

|3
|**Usability (Accessibility & i18n)**
|The frontend UI must be designed to support immediate state changes for inclusivity. Users must be able to toggle "Colorblind Mode" or switch languages (i18n) instantly without page reloads or loss of the current game state.

|4
|**Performance Efficiency**
|The integration between the backend and the Rust AI engine must handle complex pathfinding (Dijkstra) and decision-making (Minimax) asynchronously. The architecture guarantees that the React UI remains fully responsive and fluid while the bot is "thinking".

|5
|**Testability (Maintainability)**
|To achieve the mandatory 80% code coverage, the backend must strictly enforce a layered architecture (Controllers, Services, Repositories) in orther to be able do Unit Testing and isolated End-to-End testing using dynamic Docker containers.

|===
